GenResearch: Intelligent Multi-Agent Platform for Academic Research Assistance.

## Research pipeline implementation

The backend now includes the plan's typed research contracts and quality path:

- provenance-aware PDF parsing, cleanup, optional table extraction, and deterministic chunk IDs;
- section-targeted retrieval with reciprocal-rank fusion over the existing Chroma store;
- claim extraction, evidence-tag hard gates, verification verdicts, and generated-claim audit records;
- sequential section composition, redundancy detection, citation registry linting, and human-input checks;
- a single immutable draft pass followed by one citation-verification pass, one section-critic pass, and one final-QA pass; failures are surfaced for review instead of restarting drafting, while final QA uses bounded section excerpts;
- diversified scholarly retrieval across Semantic Scholar, Crossref, OpenAlex, and arXiv; duplicate records are merged, bibliographic metadata is retained for references, and a source-quality evaluation failure is flagged rather than silently accepted;
- professional DOCX formatting: Times New Roman 12-point justified body text, 16-point section headings, 14-point subsection headings, one-inch margins, and a hanging-indent reference list; generated outputs require at least five distinct cited sources by default;
- a post-draft Evidence & Visuals audit that reports quantitative claims needing verified source locations and avoids fabricating charts or equations;
- constrained chart execution, DOCX assembly, quality scorers, and fixture evaluation;
- Modal-hosted DeepSeek text generation, plus Ollama-only embeddings.

Install backend dependencies with `backend/.venv/bin/pip install -r backend/requirements.txt`.
Set `MODAL_PROXY_TOKEN_ID` and `MODAL_PROXY_TOKEN_SECRET` in `backend/.env`; chat, agents, review, and writing tasks use Modal's OpenAI-compatible endpoint with the `deepseek-ai/DeepSeek-V4.1-Flash-1017` model. The backend sends the combined bearer token and uses `top_p=0.9`. Workflow agent calls default to `reasoning_effort=none` so private reasoning does not consume their completion budget; chat continues to use `MODAL_REASONING_EFFORT`. Long-draft generation budgets scale with each section's target length, and the shared LLM client retries an output-limit response once with a larger context-safe budget and reasoning disabled. This is a bounded request-level retry, not a workflow restart; a completed draft is never regenerated by downstream checks. `MODAL_MAX_TOKENS` caps every request (default 16,384). Summarization and literature-review requests retain their respective reasoning settings. Rotate any credentials shared in chat and store only replacement values in this ignored environment file. Ollama is retained only for `OLLAMA_EMBED_MODEL` embeddings. Set `OLLAMA_BASE_URL` to the embedding server reachable from the backend. The backend never falls back to another text-generation provider. Keep `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` configured for authentication and application data. Apply `supabase/migrations/20260923_grounding_audit.sql` before running the verification audit path.

For local development, start the backend from the `backend` directory with `.venv/bin/python -m uvicorn main:app --host 0.0.0.0 --port 8000`. Prefer `python -m uvicorn` to a copied or stale `.venv/bin/uvicorn` launcher. Start the frontend separately with `cd front-end && npm run dev`.

### Deploy with Docker Compose

1. If `backend/.env` does not exist, copy `backend/env.recommended` to it; otherwise merge the template's new settings into the existing file so you do not overwrite existing credentials. Add newly rotated Modal proxy token ID and secret, Supabase credentials, and deployment-specific CORS origins.
2. Set `OLLAMA_BASE_URL` to the Ollama embedding server address reachable from the container. `localhost` inside Docker refers to the backend container; use the Ollama host's reachable address (on the Docker host, `http://host.docker.internal:11434` is available through the Compose host-gateway mapping).
3. If the root `.env` does not exist, copy `compose.env.recommended` to it; otherwise merge those variables into the existing file. Set `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, and `NEXT_PUBLIC_API_URL` (the public URL of this backend, including `https://` in production).
4. Run `docker compose up --build -d`. Check `/health` for backend liveness and `/health/ready` for Modal model-catalog access plus Ollama embedding availability. Readiness does not execute a billable generation request; verify one actual inference before accepting user traffic.

The backend runs as a non-root user. Modal and Supabase secrets are injected at runtime from `backend/.env` and are excluded from the Docker build context. Chroma, uploaded files, and scraping cache are stored in named Docker volumes. Back up `chroma_data` and `backend_storage` before upgrades or host migration. Serve the app behind HTTPS and restrict inbound ports with your deployment firewall.
Paper summarization excludes text from the References/Bibliography heading onward, groups indexed excerpts by their paper-section headings, and summarizes each section independently before drafting a reader-friendly explanation. Only sections that exceed the model context limit are split into continuation requests. Final reports are drafted one report heading per request and assembled in order; an individual heading retries with a larger output budget if the model truncates it. The pipeline does not run claim verification, citation repair, coverage gating, or external metadata lookup. Author names and publication dates are taken from indexed front matter when present, and the report retains source labels with a collapsible appendix of excerpt text. Choose Quick, Standard, or Deep detail in the UI; Standard is the default. Word targets scale by page count: Quick targets 300 words for papers up to 10 pages and 650 for longer papers; Standard targets 450/800, and Deep targets 700/1,200. Modal's configured DeepSeek model is used for section analysis and final synthesis. The UI uses `POST /agents/summarize/stream` to show live progress through loading, section analysis, note condensation when needed, and drafting.
The Literature Review agent retrieves topic-neutral evidence plus a dedicated first-page metadata pass, then extracts a bounded evidence card for each selected paper. Card findings are used in cross-paper analysis only when a verbatim quote is found in that paper's retrieved text. The review synthesis receives the evidence cards and cross-paper themes, agreements, differences, and gaps alongside the source excerpts. Review length and section targets scale with the number of papers, and deterministic writing checks prompt one repair pass for missing sections or source coverage, unsupported overclaiming language, excessive citation stacking, and missing scope statements. Results include per-paper comparison rows, quote-check counts, and any evidence-card extraction errors. The UI uses `POST /agents/literature-review/stream` to show live updates during retrieval, evidence-card extraction, cross-paper analysis, drafting, repair, and final checks.
For development hot reload, explicitly set `DEBUG=true` in `backend/.env`; it defaults to `false` so in-memory pipeline checkpoints are not discarded by reloads.

Interactive Ask AI chat and every generative agent use Modal's `deepseek-ai/DeepSeek-V4.1-Flash-1017`; only the final answer is displayed, never private reasoning. Workflow agent calls use bounded retries for empty or truncated output-limit responses; if the provider remains unavailable, the error is surfaced and there is no provider fallback. Missing Modal proxy credentials or a failed API request are surfaced. The readiness endpoint checks Modal model access and Ollama embedding availability independently. The Evidence & Visuals audit is deterministic. Document chunking remains local and deterministic, and ChromaDB remains the vector store. Ollama on `OLLAMA_BASE_URL` provides embeddings for both indexing and retrieval, using `OLLAMA_EMBED_MODEL`; transient embedding connection failures are retried with bounded backoff. Set `OLLAMA_EMBED_PREFIXES=true` for Nomic-style document/query prefixes when using `nomic-embed-text`. Re-index existing papers with `cd backend && python -m scripts.reindex_papers` before relying on semantic search, because existing indexed vectors may have been produced by a different embedding model.

The current vector backend remains Chroma for compatibility with the existing application. Qdrant, a CPU cross-encoder reranker, and Docker-level isolation for generated chart code are production upgrade paths; the chart service already enforces an import/AST allowlist and process timeout for local development.

The pipeline's Evidence & Visuals audit reuses the gathered citation registry and draft. It currently reports numerical claims and equations needing verification in the completion guide and final stream response. It does not generate charts or tables: session-ingested chunks do not retain the exact page/table provenance and extracted datapoints needed to meet the verification requirements.

## Paper discovery

Authenticated users can open **Find Papers** in the dashboard to search by topic or upload a PDF for related-paper discovery. The frontend calls `POST /search-papers`, which queries Semantic Scholar, arXiv, Crossref, and OpenAlex without requiring provider API keys, then deduplicates and ranks the results.

## Citation audit and write-and-check

Uploaded citation-audit files are extracted in the browser; the file itself is not uploaded or stored. Extracted text is sent to the citation audit endpoint for analysis, but audit results are not persisted as task results and remain in the page's results section.

The Citation Agent accepts PDF, DOCX, and UTF-8 TXT documents, or pasted text. It locally identifies citation-bearing and evidence-cue sentences without an LLM extraction call, maps numbered, author-year, DOI, and footnote citations to bibliography entries, resolves reference metadata through Crossref with Semantic Scholar/OpenAlex/arXiv title-search fallbacks, and checks passages from matching indexed papers in the user's library. The Citation Review Agent uses all indexed library papers automatically; no paper selection is required. It flags retracted metadata and possible published versions of arXiv preprints. A missing full text or an abstract-only result is marked for review; a quote is shown only when it occurs verbatim in the retrieved passage. Scanned PDFs without a text layer need OCR before upload. Audits are limited to 12 MB and 500,000 extracted characters.

The **References** dashboard page is separate from the **Citation Review Agent**. It uses the local Python document-structure parser and reuses stored references when available; it does not call an LLM, retrieve vector chunks, or perform automatic external metadata checks. References are explicitly marked `not_checked`. The Citation Review Agent audits PDF, DOCX, and TXT documents, searches for additional evidence only when requested, and records accept/reject/edit decisions in a separate review report. PDF and TXT uploads are previewed from the original file; DOCX uploads are kept intact and can be downloaded to inspect their original formatting instead of being reflowed into a reconstructed preview. The uploaded document is never modified, and accepted references can be exported separately.

Claims marked `evidence_required` or `source_mismatch` are not searched automatically. Use **Find evidence** on a claim, or select several flagged claims and use **Find evidence for selected**. The search returns up to five ranked candidates with an excerpt, support level, and score. Metadata and search results are cached in-process for 30 minutes. Accept/reject decisions and claim edits are recorded, but accepting a source never edits or inserts a citation into the document. Only references whose cited claims pass metadata and full-text checks, plus sources the user accepts, appear in the cleaned-reference and BibTeX exports.

Use **Write-and-check** to validate a passage with an optional citation and pasted evidence, or leave the citation blank to search by claim. When only an abstract is accessible, the result stays `needs_review` and cannot be rated above partial support. The corresponding API routes are `POST /agents/citations/audit`, `POST /agents/citations/audit-document`, `POST /agents/citations/find-evidence`, `POST /agents/citations/write-check`, `POST /agents/citations/decision`, and `POST /agents/citations/format`. Model token usage and audit-node latency are written through the existing Supabase observability hooks.
